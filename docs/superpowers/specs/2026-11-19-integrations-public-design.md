# Integraciones de producto y consultas publicas
Fecha: 2026-11-19. Diseno autorizado por el usuario en este chat, incluida portabilidad a clientes externos y promocion posterior tras pruebas completas.

## Alcance y flujo
La publicacion base a produccion conserva el bundle promovido desde testing. El incremento se desarrolla en codex/product-integrations-public y sigue development -> testing -> main una vez validado. La autorizacion posterior del usuario permite mover esas ramas para este incremento.

## Credenciales para proyectos externos
Usar una API HTTPS portable con claves aleatorias de 256 bits, id publico aleatorio, hash SHA-256 en reposo, expiracion maxima de 90 dias y revocacion por proyecto. No exigir cuenta AWS a clientes. Las personas administradoras gestionan claves desde la consola con JWT y permiso vigente. Mostrar el secreto una sola vez, no registrarlo ni guardarlo en navegador. La clave solo crea borradores privados y no lee, presenta, decide o publica. Idempotencia, permisos, plan y congelacion se comprueban antes de replay y transaccionalmente al crear.
Formato: loc_<32 hex keyId>_<43 base64url secret>. Header: X-Logsofchange-Key. CLI lee LOGSOFCHANGE_API_KEY del entorno, nunca argumento o archivo de credenciales; JSON de entrada explicito e Idempotency-Key requerida. Presets de origen HTTPS canonicamente limitados a los tres entornos del producto; no seguir redirects ni reintentar con otra clave.

## Plan del producto
Plan free: aprobaciones manuales actuales. Plan plus activo: integraciones y publicacion de dashboards. La fila TENANT#org / PRODUCT de AccessTable controla plan, active y expiresAt (epoch opcional); solo operacion de plataforma puede asignarla. La API no permite que un administrador de cliente se otorgue Plus. No integrar pagos ni afirmar suscripcion cobrada. Sin fila valida: free y capacidades cerradas. Plan vencido/revocado bloquea nuevos comandos de integracion/publicacion; despublicar o revocar claves permanece disponible a administradores vigentes.

## Propiedad de datos y contratos
Identidad administra claves en AccessTable: PK TENANT#org#PROJECT#project, SK INTEGRATION#keyId, secretHash, active, expiresAt epoch, scope releases:create, metadata sin secreto. Expone GET capabilities y GET/POST/DELETE integration-keys bajo /api/v1/identity/orgs/{org}/projects/{project}/.
Entregas incorpora POST /api/v1/ingestions/orgs/{org}/projects/{project}/releases con Auth NONE en gateway y validacion de clave en servicio. Reutiliza su dominio/transaccion. Proveniencia opcional source {system, externalId, revision}, acotada y tratada como texto; el servidor fija kind integration y keyId. El actor de maquina nunca suple a una persona.
Publicaciones tiene su stack propio. API privada /api/v1/publications/orgs/{org}/projects/{project}/releases/{releaseId} GET listado a nivel proyecto, POST publicar y DELETE despublicar entrega (revision en POST). POST {revision, slug, projectName, fields} con fields subconjunto de title,summary,changes e incluye title; deriva SOLO esos campos de una revision aceptada verificada consultando Evidence API con JWT del solicitante. Comprueba membresia/proyecto/administrador y plan vigentes en la transaccion. Slug global unico y fijo por proyecto; min3 max64 lowercase alnum y guion.
Tabla administrativa guarda mapping/recibos privados; tabla publica guarda SOLO DTO permitido. Lambda publico solo tiene GetItem/Query sobre tabla publica, sin acceso a permisos/entregas/evidencia/admin. GET /api/v1/public/projects/{slug} devuelve {project:{slug,name},releases:[{id publico aleatorio,revision,title,summary?,changes?,acceptedAt,publishedAt}],nextCursor}; paginacion1..50. Cuenta y metricas del dashboard usan solo publicaciones consultadas, sin inferir datos privados. Sin publicacion:404. Despublicar elimina proyeccion y futuras lecturas, sin prometer borrar copias externas.
Todas las respuestas privadas y publicas usan no-store inicialmente. Nada de HTML libre, peticiones externas, tokens, emails, sub, reason ni actas privadas en DTO publico. POST/DELETE requieren Idempotency-Key y autorizacion antes de replay.

## Experiencia
Consola /integrations para administrador: ver capacidades Plus, crear/revocar claves y copiar secreto una vez; seleccionar una entrega aceptada, slug/nombre publico y campos, previsualizar y publicar con aviso de acceso sin login; listar/despublicar. /p/:slug publico y SSR: resumen y tarjetas de revisiones publicadas, contadores sobre publicaciones, paginacion, vacio/error sin datos privados. Mantener marca y estilo actual. CLI portable para crear borrador desde cualquier proyecto con instrucciones Node24 y curl.

## Verificacion y limites
Tests de aislamiento/plan/expiry/revoke/freeze/replay/concurrencia y serializacion SDK real; no secreto persistido/expuesto; maquina no decide/publica; borrador no publica; revocacion bloquea replay; publish/unpublish y DTO publico exacto. Tests UI/CLI, buildSSR, cfn-lint de todos templates y smoke desplegado en development/testing antes de produccion. Canary sintetico Plus crea clave viaAPI, invoca CLI desde proceso con secreto solo en memoria, completa aprobacion humana, publica/consulta sin token/despublica/revoca y verifica denegaciones y limpieza.
Sin billing, altas publicas, invitaciones o adjuntos nuevos. Provision de un cliente real requiere organizacion/proyecto y personas verificadas; no inventar identidades ni permisos.
