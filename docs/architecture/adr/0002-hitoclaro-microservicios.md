# HitoClaro: marca y microservicios serverless

Fecha: 2026-11-19. Arquitectura vigente. La decisión de marca de este documento fue sustituida por [ADR0003](0003-logs-of-change-identidad.md): el producto vuelve a Logs of Change; los identificadores físicos se conservan.

El producto ayuda a agencias a cerrar hitos mediante entregas revisables, decisiones y evidencia versionada. **HitoClaro** expresa ese resultado mejor que Logs of Change, que describe registros técnicos. Identificador nuevo: `hitoclaro`. Descriptor: «Revisión de entregas y aprobaciones con evidencia». Una búsqueda de colisiones públicas no mostró un producto homónimo evidente; no constituye una comprobación registral de marca.

Se evaluaron tres caminos: mantener NestJS completo en una sola Lambda (menor separación y arranque heredado problemático), servir Angular estático desde S3 (válido para SPA pero no cumple la petición de frontend en Lambda), y separar Angular SSR e identidad, entregas y evidencia en stacks serverless propios. Se elige el tercero, siguiendo el hosting del portafolio.

CloudFront entrega Angular SSR desde una Function URL con AWS_IAM y OAC. Los bundles estáticos también los sirve la Lambda en este primer corte: simplifica la publicación atómica de HTML y assets sin cambiar el patrón pedido. Si el tráfico lo justifica, se moverán assets con hash a un bucket privado y caché de larga duración; las páginas y APIs permanecen sin caché.

Identidad es dueña de Cognito y las membresías; entregas, de sus revisiones, decisiones y recibos DynamoDB; evidencia consulta la API protegida de entregas y genera el acta sin leer su tabla. Entregas recibe permiso de lectura y comprobación transaccional de las membresías para impedir que una revocación intermedia autorice una escritura. Ese acoplamiento de autorización es explícito y acotado, sin escritura cruzada en tablas de negocio. Cada servicio tiene plantilla, API, función, permisos y logs propios; una compilación puede producir un mismo artefacto con entradas separadas, pero cada stack se actualiza por separado.

Dominios previstos: `dev.hitoclaro.lynxpardelle.com` (development), `test.hitoclaro.lynxpardelle.com` (testing), `hitoclaro.lynxpardelle.com` (main/production). Cada frontend recibe certificado ACM específico en us-east-1 y registros A/AAAA propios; no se cambian los registros de otros proyectos. La promoción sigue **development → testing → main** y el despliegue productivo tiene revisión explícita. Esta rama de arquitectura se conserva.

Se conservan la ubicación del checkout, el remoto Git histórico y los contratos NestJS existentes durante la migración. La identidad comercial, paquetes, pantalla, salud, Docker y recursos nuevos usan HitoClaro. El importador offline sólo acepta un JSON explícito, excluye secretos y jamás convierte historia en aprobación. El piloto real, sus permisos, restauración y corte necesitan evidencia propia antes de habilitar tráfico de negocio.

Referencias: [patrón OAC Lambda](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-lambda.html), [Angular SSR](https://angular.dev/guide/ssr), [PKCE Cognito](https://docs.aws.amazon.com/cognito/latest/developerguide/authorization-endpoint.html). Referencia local: `Portafolio-LynxPardelle/portfolioLynxPardelle-aws-infra/lib/stacks/frontend-stack.js` y `lynx-portfolio-angular/tools/package-ssr-lambda.mjs`.
